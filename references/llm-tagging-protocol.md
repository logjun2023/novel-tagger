# LLM 语义补标协议（省 token 版）

本地脚本已经打好：场景=对话/转场（规则）、人物（匹配）、以及关键词能命中的标签。
LLM 只负责「关键词和规则覆盖不到」的语义标签（恋爱/吵架/打脸/悬疑…），并且：

> **安全提示**：批次里是片段正文；敏感内容可能被模型安全过滤拦截——被拦就跳过该批（保持未标）、不要重试、不要复述内容；不影响本地拆书结果。

## 输入（todo_llm.py 生成）

`<lib>/llm_inbox/batch_XX.json`：

```json
{
  "batch": 1,
  "count": 12,
  "items": [
    {
      "id": "某书-c001-f002",
      "book": "某书",
      "chapter": 1,
      "chapter_title": "第一章 …",
      "local_tags": {"scene": ["对话"], "chars": ["男1", "女2", "2人"]},
      "text": "……片段文本（长片段已头尾截断）……"
    }
  ]
}
```

## 输出（你生成 batch_XX.result.json，与输入一一对应）

```json
{
  "某书-c001-f002": {
    "plot": ["恋爱", "吵架"],
    "scene": ["对话"],
    "confidence": 0.8,
    "note": "可选，一句话说明，不要展开"
  }
}
```

- 键 = 片段 ID；值 = 该片段 需要新增/删除 的标签。
- **只写要变的维度**；`local_tags` 里已有的标签不要重复输出。
- 值前缀 `-` 表示删除，例如 `"plot": ["-悬疑"]`。
- `confidence` / `note` 可选，`apply_tags.py` 只存 confidence。
- 兼容 `{"results": {…}}` 包装。

## 规则（重要）

1. 只用 `PROMPT.md` 里列出的可用值（或人物名/角色名）；没有合适的标签就少打或不打。
2. 宁缺勿滥：不确定的片段不要硬凑标签。
3. 逐条给结果，不要漏条目；不要复述正文，不要解释推理过程。
4. 一次只处理一个批次文件（默认 12 条），处理完立刻写结果文件，再处理下一批。
5. 输出只含 JSON，UTF-8 编码。

## 打标建议（提升一致性）

- `plot` 关注「这段戏在干什么」：告白/暧昧 → 恋爱；口角对喷 → 吵架；反派吃瘪 → 打脸；公开场合难堪但尚未翻脸 → 冲突。
- `scene` 只在本地标签明显不对时修正（例如引号占比高被误判对话）。
- `chars` 维度：只有人物表缺人时才补人名（新角色出场）。
- 长片段被截断（“中间省略”）时，以其头尾内容为准，不要猜中间剧情。

## 合并

```bash
python apply_tags.py --lib taglib taglib/llm_inbox/batch_01.result.json \
  --mark-batch taglib/llm_inbox/batch_01.json
```

合并后：标签并入对应维度（去重）、`source` 标记 `llm`/`rule+llm`；
加 `--mark-batch` 会把**整批**片段（包括你没改动的）都标记为已处理（`llm_done=true`），
避免下一轮重复入批浪费 token。要全部重来可加 `--redo` 重新挑批次。
